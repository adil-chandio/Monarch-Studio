# WF-02 working rules

Read root AGENTS.md first; these are style-specific refinements, not a replacement for repository safety/continuity rules.

- Trigger WF2 means this named style. Read START_HERE.md, STYLE_DNA.json, QUALITY_CONTRACT.json and knowledge/PLAYBOOK.md before designing a video.
- Latest delivered baseline is selected by style.json/workflow.json, not by guessing a version from chat. Pending artistic review is not approval.
- Premium means better shot/action/material/sound design, not more overlays. The explicit no-clutter user correction overrides vague requests for more effects.
- A whole-film request must change/assess the whole film; a small membrane tweak must be honestly labeled a focused pass. Never inflate inherited geometry/shot counts into newly authored work.
- Same-film revisions retain fixed voice/script unless scope explicitly changes. New speech requires current-session voice selection through available speech tooling; old voice IDs are not portable guarantees. No unapproved script or safety-qualifier changes.
- New topic: research and validate its mechanism, plan illustrative geometry, write/approve script and shots, render proof and actual final. Do not blindly reuse splinter mechanics or promise clinical accuracy.
- Absolute-time actor/camera evaluation; measured grip before pull; C2 controls inside shots; explicit semantic cuts; short real-scene shutter only in chosen windows and never across cuts; captions afterward.
- Every pass has its own tests, current evidence and source hashes. Historical QA must be labeled baseline. A filename/version label is not proof.
- Check existing processes before rendering; checkpoint before/after long operations and within55minutes. Disposable .runtime absence does not reopen a completed delivery.
- Verify actual encoded master and actual remote IDs/checksums; preserve all prior masters/source. Keep credits and licenses. Never commit secrets, hidden prompts or private credentials.
- Explain real changes and limits in clear Roman Urdu if appropriate. No claims of guaranteed perfection, ASMR, retention, independent clinician/ear review, ray tracing, Blender/Cycles assets or from-scratch modeling without evidence.
