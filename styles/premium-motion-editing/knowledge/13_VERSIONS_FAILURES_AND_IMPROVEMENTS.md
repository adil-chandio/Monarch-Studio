# 13 · Version chronology and the failure-improvement chain

## Version meaning

V1/V2/V3 belong to earlier work described in the supplied conversation. V2 and V4 were later recovered and directly inspected. V3's slideshow and yuv444p/browser problem were reported in the pasted earlier transcript; the current foundation does not pretend it newly measured an unavailable V3 editing project.

V4 was visibly insufficient: original English, social tags and end card remained, and its Urdu overlay was tiny. V5 repaired the localization using actual moving source clips, restored selected natural-speed narration and per-beat scene timing, integrated Roman Urdu type, cleaned branding and a compatible export. It also forced real inspection of failed cleanup methods and persistence assumptions.

V6 was an explicitly authorized enhancement after V5 delivery. It added near/far maps, perspective/extruded titles, transition variety, highlighted lower captions and more sound accents, with a small runner cleanup repair. Its master/source were separately uploaded and verified; V5 remained intact.

The latest user feedback accepts the non-caption gains but rejects the V6 lower caption pills. That yields a permanent clean-editorial policy, not a silent rewrite of either delivered version. Both original sources and their QA/IDs remain preserved.

## Why a detailed postmortem matters

“Make it better” is not a reusable instruction by itself. Each incident needs the visible symptom, cause, correction, evidence scope and regression. The complete eighteen-lesson register follows in the codex appendix and lives in `data/lessons.json`.

The most important pattern is classification error: a still-card animation was classified as a motion match; a file receipt as preserved bytes; color as object identity; a transport timeout as failed rendering; a technical pass as user approval; and intention as tool success. The workflow now keeps these categories separate.

## What is not retroactively claimed

No newly filmed/generated 3D geometry, no new image/speech generation during the V5/V6 repair, no certified ASR word alignment, no independent human listening pass, and no guaranteed pixel-perfect restoration of obscured paper. Missing older source/scratch history is explicitly listed. Honest boundaries are part of correct production, not an excuse to lower the visual standard.

## Future improvement process

Change one clearly named component or coherent set of components. Record the user's reason, keep the previous master, update the policy only when accepted, inspect representative failure-prone frames, run the full output checks and store the new delivery identity. Do not call a changed effect “approved” merely because it is newer or more complicated.
