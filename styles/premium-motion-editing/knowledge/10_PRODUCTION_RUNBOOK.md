# 10 · End-to-end production runbook

## Phase A — resume and brief

Run the repository continuity command first. Read the latest task, process ledger, delivery receipt and WF-05 policy. If work is active, execute its next step; do not create a duplicate. If an ambiguous “continue” follows a completed delivery, return/recover that verified output rather than rerendering it. Ask a targeted scope question only when no actionable work remains and the intended new change is genuinely unclear.

For a new request, open one active task and capture the visible instruction. Read `FRESH_CHAT.md`, the approved profile and the reference case. Decide whether the supplied video is a style reference or the actual content to adapt. Record topic, audience, takeaway, claims, language, format, duration, rights, voice state and delivery destination.

## Phase B — source and concept

Inspect the actual reference. Inventory available assets and previous versions before generating anything. Build a claim ledger and a semantic beat map. Select a coherent metaphor system and a fresh concept; record why alternatives were rejected. Confirm that the plan contains independent subject/layer changes, not only whole-frame zooms.

## Phase C — script and voice

Translate/write concise easy Urdu-English that retains causality and emphasis. Reuse selected audio when revising the same script. For new narration, obey the current tool's registration/selection rules; do not reuse stale session voice IDs as though they were durable audio. Save clip files/hashes and measure their real durations. Picture timing follows natural speech unless a speed change is explicitly requested.

## Phase D — shot construction

Prepare licensed/provided/native-motion or independently animated clips. Clean the old labels/social UI when adapting a flattened source, using source-specific masks. Annotate complete-subject depth plateaus and protected details. Place short integrated type into the remaining space. Choose each transition for narrative purpose. Keep the rejected lower-caption UI off.

## Phase E — prototype and full render

Build representative frames and short motion samples internally: opening, largest subject, longest headline, strongest depth transform, transition, and ending. Review them rather than asking the user to approve every trivial step. Fix real failures before the full export. Start one recorded background job; do not run long-lived work through an uncontrolled shell timeout.

Run the full encode, then inspect the encoded output—not just source frames. Repeat only the failed/changed stage with an explicit reason. Preserve successful source clips, voice and records. Do not regenerate a whole project because one title or mask failed.

## Phase F — QA and delivery

Check format/codec/frame count/faststart/full decode, audio levels, subject integrity, actual motion, typography, caption policy, tags/end card and semantic sync. Record review scope honestly. Present the existing final file. Upload it to the project's WF-05 Drive area, independently retrieve its metadata and compare size/hash. Upload a source recovery bundle and verify it too.

Update the project/registry links, checkpoint, archive the accepted small source/knowledge and only then clear the active slot. Stop the task's periodic watcher after the task is complete; do not kill a healthy production render to make a status message look tidy.
